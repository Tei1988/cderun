# cderun 実装ガイド

## 概要

このドキュメントは`cderun`の実装を段階的に進めるためのガイドです。
各ステップは依存関係を考慮して順序付けられており、前のステップが完了してから次に進みます。

### Phase 6: 高度な設定解決機能 (New)

このフェーズでは、設定ファイルの検索能力を向上させ、より動的で柔軟な値の解決メカニズムを導入する。

### Step 6.1: 設定ファイルの検索とマージ

**目的**: 親ディレクトリへの探索機能を追加し、見つかった複数の設定ファイルを階層的にマージする。

**実装方針**:
1.  **ファイル検索**:
    -   `config.LoadCDERunConfig` および `config.LoadToolsConfig` を変更。
    -   カレントディレクトリからルートディレクトリ (`/`) まで親を遡り、設定ファイルを探すロジックを追加する。
    -   見つかったすべてのファイルのパスを、優先順位の高い（カレントディレクトリに近い）順でリストに保持する。
    -   その後、ユーザーのホームディレクトリ、システム全体のパスをリストに追加する。
2.  **設定のマージ**:
    -   検索して見つかったすべての設定ファイルを、優先順位の低い（システム全体→ホーム→親→...→カレント）順で読み込む。
    -   読み込んだ設定オブジェクトを、再帰的にマージしていく。後からマージする（優先順位の高い）設定が、既存の値を上書きするようにする。
    -   Goのライブラリ `mergo` の利用を検討する ( `mergo.Merge(&dest, src, mergo.WithOverride)` )。

### Step 6.2: 値の動的解決 (cderun Expressions)

**目的**: 設定ファイル内の値を動的に解決する「cderun Expressions」 (`{{...}}`) を実装する。

**実装方針**:
1.  **Resolverコンポーネント**:
    -   `config` パッケージ内に、式の解決ロジックを担当する新しいコンポーネント（例: `ExpressionResolver`）を作成する。
    -   このリゾルバは、設定オブジェクト（`map[string]any`など）を再帰的に探索し、文字列値に含まれる `{{...}}` を見つけて置換する責務を持つ。
2.  **式のパース**:
    -   正規表現 `\{\{([^}]+)\}\}` を用いて、式の中身を抽出する。
3.  **マジックワード解決**:
    -   `HOME`, `PWD` などのマジックワードを解決するロジックを実装する。
4.  **`file` ディレクティブ解決**:
    -   式の中身が `file:<filename>` 形式の場合、ファイル名を抽出する。
    -   Step 6.1で実装したファイル検索ロジックを再利用し、指定されたファイルを探す。
    -   ファイルの内容を読み込み、文字列として返す。

### Step 6.3: パスの解決 (チルダ・相対パス)

**目的**: 値解決後のパス文字列に対し、チルダ展開と相対パス解決を行う。

**実装方針**:
1.  **コンテキストの保持**:
    -   設定ファイルをマージする際、および `ExpressionResolver` が値を解決する際に、その値がどの設定ファイルから来たものか（ファイルの絶対パス）を追跡できるようにする。
2.  **パスの変換**:
    -   `ExpressionResolver` が式の解決を終えた後、対象のキー（`volumes`のホストパス、`logging.file`, `socketPath` など）の値を順次解決する。
    -   **チルダ展開**: 値が `~` または `~/` で始まる場合、`os.UserHomeDir()` を使ってホームディレクトリの絶対パスに置換する。
    -   **相対パス解決**: 上記の結果、値が `./` や `../` で始まる場合、その値の出所となった設定ファイルのディレクトリパスを基準に、`filepath.Join` を使って絶対パスに変換する。
    -   `filepath.Clean` を使って、最終的なパス文字列（例: `{{PWD}}/../src`）を正規化する。
