# Feature: Strict Argument Parsing Strategy (Completed)

## 概要

`cderun` はラッパーツールであり、自身のフラグと、ラップする対象（コンテナ内で実行するコマンド）への引数を厳密に区別する。また、最初の非フラグ引数である「サブコマンド」をキーとして設定を解決し、最終的に実行するコンテナイメージとコマンドを決定する。

## パースのルール

### 1. 引数の識別と役割

`cderun` に渡される引数は、以下の優先順位で解釈される。

`cderun [cderun-flags] <subcommand> [subcommand-args]`

- **[cderun-flags]**: `cderun` 自体の動作を制御するフラグ。これらはサブコマンド名の**前**に配置される標準フラグ（P2）と、`--cderun-` で始まる内部オーバーライドフラグ（P1）に分けられる。
- **\<subcommand\>**: 最初の非フラグ引数。これは `.tools.yaml` から設定を読み込むための**キー**としてのみ使用される。コンテナ内で実行されるコマンド（`CMD`）には、明示的に設定されていない限り含まれない。
- **[subcommand-args]**: サブコマンド名より**後**にある引数。これらはコンテナ内で実行されるコマンドの引数として渡される。`--cderun-` で始まるフラグ（P1）が含まれる場合、それらはパースのために前方に移動（Hoisting）される。

### 2. イメージ名の決定 (Step 10.1)

`cderun` がコンテナを実行するためのイメージ名は、以下の優先順位ルールで決定される。

1. **CLIフラグ (P1/P2)**:
  - `--image` または `--cderun-image` フラグが指定されている場合、最優先で使用される。
2. **環境変数 (P3)**:
  - CLIフラグがない場合、`CDERUN_IMAGE` 環境変数の値が使用される。
3. **サブコマンド（キー）による検索 (P4)**:
  - 上記がない場合、`<subcommand>` をキーとして `.tools.yaml` からツール定義を検索し、その `image` を使用する。
4. **グローバルデフォルト (P5)**:
  - 上記がない場合、`.cderun.yaml` のグローバル設定が使用される。
5. **最終的なイメージ名の決定とエラー**:
  - 上記のいずれでもイメージ名が特定できなかった場合、`cderun` はエラーとして終了する。

### 3. コンテナに渡されるコマンド (Step 10.2)

`cderun` がコンテナ内で実行するために渡すコマンドは、以下のルールで組み立てられる。

1. **サブコマンドの役割**:
  - `<subcommand>` は、設定を解決するための**純粋なキー**としてのみ使用される。
2. **コマンドの構成**:
  - コンテナに渡されるコマンド（`CMD`）は、ツール定義で指定された `command` と、サブコマンド名以降の全ての引数（`[subcommand-args]`）を結合したものになる。
  - `<subcommand>` 自体は、コンテナの `CMD` には含まれない。

### 4. 挙動の詳細

**例1: ツール定義がある場合 (`.tools.yaml` に `my-tool` があり `image: alpine`, `entrypoint: ["/usr/bin/my-tool-impl"]`, `command: ["my-tool"]` と定義)**

```bash
cderun my-tool -l -a
```
- `<subcommand>`: `my-tool`
- イメージ: `alpine` (ツール定義から)
- コンテナ `ENTRYPOINT`: `/usr/bin/my-tool-impl` (ツール定義から)
- コンテナ `CMD`: `["my-tool", "-l", "-a"]` (定義された `command` + `passthrough args`)
- 結果: コンテナ内で `/usr/bin/my-tool-impl my-tool -l -a` が実行される。

**例2: ツール定義がない場合 (`go` は `.tools.yaml` に定義なし)**

アドホックな実行を行う場合、サブコマンドは常に設定のキーとして消費されることに注意してください。サブコマンド自体をコンテナ内で実行したい場合は、イメージのデフォルト `ENTRYPOINT` がそのコマンドであるか、あるいは `--entrypoint` フラグで明示的に指定する必要があります。

```bash
cderun --image=golang:1.22 --entrypoint go go --version
```
- `<subcommand>`: `go`
- イメージ: `golang:1.22` (`--image` フラグから)
- コンテナ `ENTRYPOINT`: `go` (`--entrypoint` フラグから)
- コンテナ `CMD`: `["--version"]` (`go` はキーとして消費され、含まれない)
- 結果: コンテナ内で `go --version` が実行される。

**例3: ツール定義がなく、かつ `--image` もない場合**

```bash
cderun go --version
```
*   `<subcommand>`: `go`
*   イメージ: 特定できない。
*   結果: **エラー** (イメージ名が特定できないため)。

### 5. cderun内部オーバーライド (P1) の例外

`--cderun-` で始まるフラグ（P1内部オーバーライド）は、サブコマンド名より後に指定された場合でも、前処理（Hoisting）によってサブコマンドの前に移動され、`cderun` 自体の設定として常に解釈される。

## テストケース要件
以下のコマンドを実行した際の結果が保証されるテストを作成すること。

```bash
cderun --tty docker --tty
```
