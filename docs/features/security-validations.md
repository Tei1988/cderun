# セキュリティ・バリデーション (Security Validations)

`cderun` は、ホスト環境の安全性と設定の整合性を維持するため、複数のレイヤーでバリデーションと保護策を実装しています。

## 1. 引数ホイスティングによるフラグの分離

`cderun` は、自身のフラグ（`cderun` の動作設定）と、コンテナ内で実行されるサブコマンドの引数を厳密に区別します。

- **境界の確立**: 最初の非フラグ引数を「サブコマンド」として認識し、それ以降を「パススルー引数」として扱います。
- **P1 Internal Overrides の安全な処理**: `--cderun-` プレフィックスが付いたフラグのみを前方に移動（ホイスト）させることで、ラップされたツールが `--tty` などの同名フラグを持っていても、意図せず `cderun` の動作が変更されることを防ぎます。

詳細は [引数解析](./argument-parsing.md) を参照してください。

## 2. cderun式（Expressions）のセキュリティ制約

`{{file:...}}` や `{{find_dir:...}}` などの動的解決ディレクティブには、情報漏洩やリソース枯渇を防ぐための制限があります。

- **パス・トラバーサルの防止**:
  - `file` および `find_dir` ディレクティブで指定されるパス名は、絶対パスであってはなりません。
  - パス名に `..`（親ディレクトリ参照）を含めることは禁止されています。
  - これらの検証には `filepath.IsLocal` 相当のロジックが使用され、プロジェクト外の重要なファイル（例: `/etc/passwd`）へのアクセスを遮断します。
- **ファイルサイズ制限**:
  - `{{file:...}}` で読み込めるファイルサイズは最大 **1MB (1,048,576 bytes)** に制限されています。
  - 読み込み前に `fs.Stat` でサイズを確認し、超過している場合はエラーを返します。これにより、巨大なファイルを読み込ませることでメモリを枯渇させる DoS 攻撃を防ぎます。

## 3. スティッキーエラー (Sticky Error) による不完全な実行の防止

値の解決プロセス（式の展開など）中にバリデーションエラーが発生した場合、`ExpressionResolver` はそのエラーを内部に保持し、以降の解決処理を実質的にスキップします。

- **挙動**: エラー発生後の解決リクエストは、元の値をそのまま返します。
- **目的**: 複数の設定値がある場合に、一部が正常で一部が異常な状態でコンテナが起動してしまう「中途半端な状態」を回避し、確実にエラーとして停止させます。

## 4. スナップショットの保護

ネスト実行のために作成される一時的な設定スナップショット（`/tmp/cderun-snap-*`）は、適切なパーミッションで管理されます。

- **ディレクトリ権限**: `0700` (所有者のみアクセス可能)
- **ファイル権限**: `0600` (所有者のみ読み書き可能)

これにより、同一ホスト上の他のユーザーがスナップショット内の機密設定を盗み見ることを防ぎます。

## 5. 実行環境の分離

`cderun` はデフォルトでホストの環境変数をコンテナに引き継ぎません。

- **明示的な指定**: 必要最低限の環境変数のみを `--env` フラグで明示的に指定することを推奨しています。
- **Strict Env モード**: `--strict-env` フラグを有効にすると、指定された環境変数がホストに存在しない場合に実行を拒否し、設定ミスによる予期せぬ動作を防止します。
