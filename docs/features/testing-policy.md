# E2E テスト設計方針 (E2E Testing Policy)

## 1. 概要

`cderun` では、実際のコンテナランタイム環境における動作を保証するため、Docker の複数バージョンを用いた E2E テストを実施している。
本ドキュメントでは、E2E テストの設計思想、CI 構成、およびテスト拡充の際のガイドラインを定義する。

## 2. Docker バージョン別のリアルテスト

### 2.1. docker:dind の採用理由

`cderun` は Docker API を直接操作し、ボリュームマウントやデバイスマウント、ネスト実行などの高度な機能を提供する。これらの挙動は、Docker デーモンのバージョンや環境（ストレージドライバ等）によって微妙に異なる場合がある。
モックを用いたテストではこれらの差異を検出できないため、GitHub Actions のサービスコンテナとして `docker:dind` (Docker-in-Docker) を採用し、実際のデーモンに対してテストを実行する。

### 2.2. マトリックス戦略

以下の 3 つの世代を主要なターゲットとして継続的に検証する。

- **20.10**: 旧安定版。レガシーな環境との互換性維持を確認する。
- **24.0**: 現在広く普及しているバージョン。
- **27.0**: 最新版。最新の API 挙動やセキュリティアップデートへの対応を確認する。

## 3. CI 実行効率の最適化

テストの実行時間を短縮し、開発者に迅速なフィードバックを提供するため、以下の CI 戦略を採用している。

### 3.1. ジョブ의分離とバイナリ共有

1. **Build ジョブ**: 最初に `cderun` バイナリを 1 回だけビルドし、GitHub Actions の Artifacts として保存する。
2. **Unit Test ジョブ**: ユニットテストとカバレッジ測定を、マトリックス外の単一ジョブで実行する。
3. **E2E Test ジョブ**: 保存されたバイナリをダウンロードして使用する。これにより、マトリックス内の各ジョブでの冗長なコンパイル時間を削減する。

### 3.2. E2E テストのフィルタリング

E2E テストジョブでは、`-tags=e2e` を指定した上で、`-run "^(TestE2E_|TestScenario_)"` フラグを使用して E2E テストのみをピンポイントで実行する。これにより、マトリックス内でユニットテストが繰り返し実行されるのを防ぐ。

## 4. CI 環境特有のパス解決

### 4.1. ホストパス vs DinD コンテナパス

GitHub Actions で DinD を使用する場合、テストを実行する Runner (ホスト) と、Docker デーモンが動作する DinD コンテナは別物である。
Runner 上のファイルをコンテナにマウントする場合、Docker デーモンからは Runner のパスが直接見えない。

この課題を解決するため、以下の対策を講じている。

1. **共通ボリュームのマウント**: CI 設定において Runner のワークスペース (`/home/runner/work`) を DinD コンテナの同じパスにマウントしている。
2. **一時ディレクトリの制御**: テスト内で `t.TempDir()` を使用する際、環境変数 `TEST_HOST_TMP_DIR` を通じてベースパスを Runner/DinD 間で共有された領域に切り替え可能にしている。
   - **注意点**: `os.MkdirTemp` 等で作成した一時ディレクトリは、テスト終了後に `t.Cleanup` で確実に削除すること。

### 4.2. バイナリの解決

E2E テスト中に `cderun` 自体をコンテナにマウントする場合（ネスト実行等）、ヘルパー関数 `findCderunBinary` を使用して、プロジェクトルートにあるビルド済みバイナリを動的に解決する。

## 5. E2E テスト実装ガイドライン

### 5.1. 基本ルール

- **命名規則**: 新しい E2E テストは `TestE2E_` または `TestScenario_` で始めること（CI でのフィルタリングのため）。
- **ビルドタグ**: ファイル先頭に `//go:build e2e` を付与する。
- **セパレータ `--` の使用**: `cderun` のフラグと実行コマンドの境界を明確にするため、常に `--` セパレータを使用すること。
  - 例: `cderun [cderun-flags] -- [target-command]`
  - ヘルパー関数 `runCderunE2E` または `runCderunWithStdinE2E` を使用することで、この境界を安全に管理できる。
- **堅牢な実行**: Alpine 等の最小限のイメージを使用する場合、`--entrypoint sh` を明示し、`sh -c '...'` 形式でコマンドを実行することを推奨する。

### 5.2. リアル環境の利用

- **診断モード**: `TestE2E_DockerVersion` で `--diagnosis` を実行し、対象の Docker バージョンをログに残す。
- **ネスト実行 (DooD)**: ホストの Docker ソケットと `cderun` バイナリをマウントし、コンテナ内からのコンテナ起動を検証する。内側の `cderun` 呼び出しでも `--` セパレータを忘れずに配置すること。
