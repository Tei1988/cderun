# Feature: Nested Execution (Nested cderun) (Specification)

## 概要

`cderun` をコンテナ内からさらに実行する「ネスト実行」において、基底ホスト（物理マシン等）の設定を引き継ぎ、適切にマウントや環境構築を行うための仕様。

## 背景と課題

### 1. 設定の不連続性
通常、コンテナ内で実行される `cderun` は、実行ホスト（コンテナ）内の `.cderun.yaml` や `.tools.yaml` しか参照できません。基底ホストで定義された便利なツール定義やグローバル設定が失われてしまいます。

### 2. Overlay in Overlay 問題（マウントの失敗）
基底ホストのDockerデーモンを共有してコンテナを実行する場合、`docker run -v` に渡すパスは**基底ホスト上のパス**である必要があります。
実行ホスト（コンテナ）上のパスをそのままマウントしようとすると、基底ホスト側にそのパスが存在しない（または別の内容である）ため、マウントに失敗します。

## 解決策

### 1. 動的な設定ファイルの生成と注入

`--mount-cderun` が指定された場合、`cderun` は現在の実行環境で解決された設定を一時ファイルとして書き出し、それをターゲットコンテナに注入します。

#### 動作フロー
1.  **設定の集約**: 実行ホストが読み込んだ全ての `.cderun.yaml` と、実行中のツールに関連する `.tools.yaml` の設定をマージします。
2.  **一時ディレクトリの作成**: 実行ホストの `/tmp/cderun-<UUID>/` に、マージ済みの `.cderun.yaml` と `.tools.yaml` を作成します。
3.  **コンテナへのマウント**: 作成したディレクトリを、ターゲットコンテナの `/run/cderun/` にマウントします。
    - `-v /tmp/cderun-<UUID>/:/run/cderun/:ro`
4.  **検索パスの追加**: コンテナ内の `cderun` は、設定ファイルの検索パスに `/run/cderun/` を追加します。

### 2. 基底ホストパスの変換ロジック

「Overlay in Overlay」問題を解決するため、`.cderun.yaml` にネスト情報とパスのマッピングを保持します。

#### 設定の拡張例 (`/run/cderun/.cderun.yaml`)
```yaml
nested:
  nestLevel: 1
  baseHostPaths:
    - hostPath: "/home/user/project"
      containerPath: "/workspace"
```

#### パス変換の仕組み
コンテナ内の `cderun` が `-v ./src:/app` のようなマウントを要求された場合：
1.  `./src` をコンテナ内の絶対パス（例: `/workspace/src`）に変換します。
2.  `baseHostPaths` を走査し、`/workspace/src` が `containerPath: /workspace` の配下にあることを確認します。
3.  対応する `hostPath` を使って、基底ホスト上のパス `/home/user/project/src` に置換します。
4.  Dockerデーモンには `-v /home/user/project/src:/app` として命令を発行します。

これにより、コンテナ内からでも「自分自身のディレクトリ」を正しく次のコンテナに引き継ぐことが可能になります。

## 設定ファイルの検索優先順位

ネスト実行をサポートするため、設定ファイルの検索順序を以下のように更新します（上ほど優先度が高い）。

1.  **P1: cderun内部オーバーライド** (`--cderun-*` フラグ)
2.  **P2: コマンドライン引数**
3.  **P3: 環境変数**
4.  **P4: ツール固有設定** (`.tools.yaml`)
    - カレントディレクトリから親へ遡って検索
    - `~/.config/cderun/.tools.yaml`
    - `/etc/cderun/.tools.yaml`
    - **/run/cderun/.tools.yaml** (ネスト注入された設定)
5.  **P5: cderunデフォルト設定** (`.cderun.yaml`)
    - カレントディレクトリから親へ遡って検索
    - `~/.config/cderun/.cderun.yaml`
    - `/etc/cderun/.cderun.yaml`
    - **/run/cderun/.cderun.yaml** (ネスト注入された設定)
6.  **P6: ハードコードされたデフォルト値**

※ `/run/cderun/` は「真のデフォルト」として機能し、ユーザーがコンテナ内で明示的に用意した設定ファイルがある場合はそちらが優先されます。

## ライフサイクル管理

- **作成**: `--mount-cderun` を伴う実行において、コンテナ起動プロセスの途中で生成されます。
- **削除**: コンテナが終了（または `cderun` プロセスが終了）した際に、実行ホスト上の `/tmp/cderun-<UUID>/` を再帰的に削除します。

## 制限事項・注意事項

- **ランタイムソケットの共有**: この機能は、ネストされた `cderun` が基底ホストのDockerデーモン（ソケット）にアクセスできることを前提としています。
- **UUIDの衝突**: 非常に低い確率ですが、UUIDの衝突を避けるための実装（リトライ等）が推奨されます。
- **クリーンアップの保証**: 予期せぬ中断時にも一時ファイルが残らないよう、シグナルハンドリングによるクリーンアップが必要です。
