# E2E テスト (完了)

## 1. 概要

`cderun` における E2E テストは、実際のコンテナランタイム（Docker または Podman）を使用して、システム全体の動作をエンドツーエンドで検証することを目的とする。
ユニットテストや、モックランタイムを使用した統合テストではカバーできない、実際のデバイスマウント、バイナリの実行、コンテナのライフサイクル、OSシグナルの挙動などを実環境で保証する。

## 2. テストの分類

プロジェクトでは、テストを以下の 3 つのカテゴリに分類している。

| カテゴリ | 目的 | 実装の特徴 |
| :--- | :--- | :--- |
| **Unit (ユニット)** | 個別の関数やメソッドの論理的な正当性を検証。 | 外部依存なし。高速。 |
| **Integration (統合)** | コンポーネント間の連携を検証。 | `MockRuntime` を使用してランタイムをシミュレート。ファイルシステム操作を含む場合がある。 |
| **E2E (エンドツーエンド)** | ユーザー視点でのシステム全体の動作を検証。 | **実際の Docker/Podman を使用。** `//go:build e2e` タグを付与。 |

## 3. 実装方針

E2E テストを実装する際は、以下のガイドラインに従うこと。

### 3.1. ビルドタグの使用

E2E テストファイルには、必ずファイルの先頭に `//go:build e2e` ビルドタグを付与すること。
これにより、通常の `go test ./...` 実行時には E2E テストが除外され、テスト実行時間の増大や環境依存による失敗を防ぐことができる。

### 3.2. テストヘルパーの活用

`internal/command/test_helpers_test.go` に用意されているヘルパー関数を使用する。

- `runCderun(args ...string)`: `cderun` コマンドをプロセス内で実行し、標準出力、標準エラー出力、終了コードを取得する。
- `skipIfDockerBroken(t, err)`: Docker 環境が利用できない、または特定の制限（OverlayFS 上でのマウント制限など）がある環境でテストを適切にスキップする。

### 3.3. クリーンアップ

テストで使用した一時ディレクトリや設定ファイルは、`t.TempDir()` や `t.Cleanup()` を使用して確実に削除すること。
ただし、コンテナの削除については `cderun` のデフォルト挙動（`--remove=true`）に任せるか、明示的に制御する。

## 4. 実行方法

E2E テストを実行するには、`-tags=e2e` フラグを明示的に指定する必要がある。

```bash
# すべての E2E テストを実行
go test -v -tags=e2e ./...

# Makefile ターゲットを使用
make test-e2e
```

## 5. 主要なテストシナリオ

以下の項目は、実際のランタイム環境を必要とするため、E2E テストでの検証が推奨される。

- **デバイスマウント**: `--device` フラグによるホストデバイスのコンテナ内へのマウントと、コンテナ内からのアクセス。
- **実際のバイナリ実行**: 特定のイメージ（Alpine, Node.js 等）を使用して、期待されるバイナリが正しく実行され、出力が得られること。
- **高度なネスト実行**: ホストのソケットとバイナリをマウントし、コンテナ内からさらにコンテナを起動する一連のフロー。
- **インタラクティブ動作**: TTY が割り当てられた状態での疑似的な対話操作やシグナル転送（可能であれば）。
